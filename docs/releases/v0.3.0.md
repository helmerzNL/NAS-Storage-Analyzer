# 🇳🇱 Nederlands

## Highlights

Voor platforms die per app één container draaien, de Community Applications-store van Unraid en Home Assistant, is er nu een **all-in-one image**: PostgreSQL, de webinterface en de worker in één container, met alles in één map. Docker Compose blijft de aanbevolen route; er verandert niets aan je Compose-bestand, je `.env` of je database.

Al het andere van `v0.2.0` zit er ook in: installeren en bijwerken zonder bouwen, uitnodigen met een link, back-up en herstel in de app, verwijderscripts voor bestanden en mappen, en een auditlog dat elke scanuitkomst bewaart. De volledige lijst staat in [`v0.2.0.md`](v0.2.0.md).

## ✨ Nieuw

- **All-in-one image** (#34): `ghcr.io/helmerznl/nas-storage-analyzer-aio`, met dezelfde tags als het gewone image (`latest`, `beta`, `beta-<sha>` en een versienummer; amd64 en arm64). Het is gebouwd op het gewone image, op dezelfde digest, dus het draait precies dezelfde binary.
  - **Eén map:** `/data`; de database staat in `/data/postgres`. Een lege map wordt bij de eerste start een database. Een map van een andere PostgreSQL-hoofdversie, of een volle map zonder database, wordt geweigerd en niet aangeraakt.
  - **De sleutel blijft van jou:** `NASSA_ENCRYPTION_KEY` (of `NASSA_ENCRYPTION_KEY_FILE`) is verplicht. Zonder sleutel start de container niet en zegt hij hoe je er een maakt: `docker run --rm ghcr.io/helmerznl/nas-storage-analyzer-aio genkey`. Bewaar hem buiten `/data` en de back-ups daarvan.
  - **Geen databasewachtwoord:** PostgreSQL luistert alleen op zijn unix-socket in de container, niet op een TCP-poort, dus er is geen geheim om te maken of te vernieuwen.
  - **Shares:** mount de map met shares alleen-lezen en zet `NASSA_SHARES_ROOT` erop (op Unraid `/mnt/user`, op beide plaatsen hetzelfde pad). Met `NASSA_SHARES_GID=100` leest de app shares van `nobody:users`. Geef je de container `CAP_SYS_ADMIN`, dan draait de worker als root en kan hij zelf NFS mounten; zonder die rechten draait niets als root behalve het startscript. _Voor SMB is dat in deze versie niet genoeg: `mount.cifs` vraagt ook `CAP_DAC_READ_SEARCH`, zie [`v0.3.1.md`](v0.3.1.md)._
  - **Stoppen:** `docker stop` stopt eerst de webinterface en de worker en daarna PostgreSQL netjes. Stopt een van de drie zelf, dan stopt de container met een fout, zodat Docker of Home Assistant hem opnieuw start. Geef hem `--shm-size=256m`; met minder gebruikt PostgreSQL bestanden in `/data` en zegt het image dat in de log.
  - **Van Compose naar all-in-one en terug:** mount `DATA_PATH` als `/data`; de database `DATA_PATH/postgres` wordt met zijn gegevens overgenomen (met dezelfde `NASSA_ENCRYPTION_KEY`).
  - Uitleg, een voorbeeld en de afwegingen: [`docs/deploy.md` §8b](../deploy.md#8b-all-in-one-image-unraid-store-en-home-assistant) en [ADR 0013](../adr/0013-all-in-one-image.md).
- **Een README volgens het Flux76-sjabloon** (#32), in het Nederlands en het Engels: een kop met logo en taalwisselaar, kenmerken, screenshots, snel starten, configuratie, back-ups, architectuur en privacy.

# 🇬🇧 English

## Highlights

For platforms that run one container per app, the Unraid Community Applications store and Home Assistant, there is now an **all-in-one image**: PostgreSQL, the web interface and the worker in one container, with everything in one folder. Docker Compose remains the recommended route; nothing changes in your Compose file, your `.env` or your database.

Everything else from `v0.2.0` is in as well: install and update without building, invite with a link, backup and restore in the app, delete scripts for files and folders, and an audit log that keeps every scan outcome. The full list is in [`v0.2.0.md`](v0.2.0.md).

## ✨ New

- **All-in-one image** (#34): `ghcr.io/helmerznl/nas-storage-analyzer-aio`, with the same tags as the regular image (`latest`, `beta`, `beta-<sha>` and a version number; amd64 and arm64). It is built on the regular image, on the same digest, so it runs exactly the same binary.
  - **One folder:** `/data`; the database is in `/data/postgres`. An empty folder becomes a database on the first start. A folder of another PostgreSQL major version, or a non-empty folder without a database, is refused and not touched.
  - **The key stays yours:** `NASSA_ENCRYPTION_KEY` (or `NASSA_ENCRYPTION_KEY_FILE`) is required. Without it the container does not start and says how to make one: `docker run --rm ghcr.io/helmerznl/nas-storage-analyzer-aio genkey`. Keep it outside `/data` and its backups.
  - **No database password:** PostgreSQL listens on its unix socket inside the container only, not on a TCP port, so there is no secret to make or rotate.
  - **Shares:** mount the folder with the shares read-only and set `NASSA_SHARES_ROOT` to it (on Unraid `/mnt/user`, the same path in both places). With `NASSA_SHARES_GID=100` the app reads shares of `nobody:users`. If you give the container `CAP_SYS_ADMIN`, the worker runs as root and can mount NFS itself; without those rights nothing runs as root but the start script. _For SMB that is not enough in this version: `mount.cifs` also asks for `CAP_DAC_READ_SEARCH`, see [`v0.3.1.md`](v0.3.1.md)._
  - **Stopping:** `docker stop` stops the web interface and the worker first, then PostgreSQL cleanly. If one of the three stops by itself, the container exits with an error, so Docker or Home Assistant starts it again. Give it `--shm-size=256m`; with less, PostgreSQL uses files in `/data` and the image says so in the log.
  - **From Compose to all-in-one and back:** mount `DATA_PATH` as `/data`; the database `DATA_PATH/postgres` is taken over with its data (with the same `NASSA_ENCRYPTION_KEY`).
  - Explanation, an example and the trade-offs: [`docs/deploy.md` §8b](../deploy.md#8b-all-in-one-image-unraid-store-en-home-assistant) and [ADR 0013](../adr/0013-all-in-one-image.md).
- **A README that follows the Flux76 template** (#32), in Dutch and English: a header with logo and language switch, features, screenshots, getting started, configuration, backups, architecture and privacy.

## ⚠️ Upgrade notes

- **Are you running `0.2.0` (the image of 3 November)?** Then there is nothing to do: `0.3.0` changes nothing in `docker-compose.yml`, `.env.example` or the database, and there are no new migrations. Pull the image (`docker compose pull`, then `docker compose up -d`; *Redeploy* in a stack manager does not fetch a moving tag by itself).
- **Coming from before `0.2.0`?** Then first do the update steps of [`v0.2.0.md`](v0.2.0.md) (the heading *Upgrade notes*). In short: take a backup (migrations `0005`, `0006` and `0007` cannot be undone), rename the variables with `sed -i 's/^NASA_/NASSA_/' .env` (an old `.env` is refused), move the database from the volume `db-data` to an absolute folder `DATA_PATH` with `scripts/migrate_data.sh`, and replace your `docker-compose.yml` with the one of this version.
- **Want to try the all-in-one image?** See [`docs/deploy.md` §8b](../deploy.md#8b-all-in-one-image-unraid-store-en-home-assistant). The package `nas-storage-analyzer-aio` may need to be made public on GHCR once before Unraid or Home Assistant can pull it without signing in.
